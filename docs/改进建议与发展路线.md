## BuddyDesk 改进建议与发展路线

基于对项目全部 ~30 个模块的深度代码审查，以下是按优先级排列的发现与建议。

---

### 一、当前存在的关键问题

#### 1. 安全风险（最高优先级）

命令引擎是整个项目的核心创新，也是最大的风险点。当前 `[SHELL:...]` 标签会执行 AI 回复中的任意命令，而防御手段是基于黑名单的模式匹配（`DANGEROUS_PATTERNS`）。这套机制可以被轻松绕过，比如：

- `powershell -enc <base64>` 绕过编码检测
- `cmd /c "echo Y | format C:"` 利用管道绕过
- `python -c "import os; os.system('...')"` 完全不在检测范围内
- `certutil -decode`、`msiexec /i` 等危险命令未被覆盖

另外，`command_engine.py` 第 358 行的 shell 元字符清理不完整，遗漏了 `^`、`<`、`>`、`%`、`!` 等 cmd.exe 特殊字符，存在注入风险。

**建议**：将所有 shell 命令改为"默认需确认"，仅对明确安全的应用启动（`[APP:...]`）免确认。长远来看应引入命令白名单机制，而非黑名单。

#### 2. 已发现的运行时 Bug

审查中发现了两个会导致崩溃的 bug：

- `ui/chat_window.py` 的 `_refresh_md` 方法引用了未定义的变量 `text`（第 559 行），当用户调整字体大小时会触发 `NameError` 崩溃。
- `ui/settings_panel.py` 使用了 `QMessageBox` 但从未 import，用户点击"崩溃上报"相关按钮时会崩溃。

其他值得注意的问题：

- `bridge.py` 的取消机制实际不生效——`prev_cancelled` 始终为 `False`，快速连续发送消息时，旧请求的回调仍会执行，可能导致过期回复覆盖新回复。
- `pixel_pet.py` 的 ZZZ 浮动文字颜色硬编码为 `(180, 180, 220)`，但定义的 `ZZZ_COLOR` 是 `#7B8CDE`（即 `123, 140, 222`），睡觉时的 ZZZ 显示颜色不对。
- `chat_window.py` 的任务跳过动画使用了 `windowOpacity` 属性，但这只对顶层窗口生效，子控件无法淡出，会直接消失。

#### 3. 性能瓶颈

- **GUI 线程阻塞**：聊天窗口拖入文件时同步读取文件内容、启动器检测 Claude CLI 时同步调用 `subprocess.run`（最多等 5 秒）、像素宠右键菜单同步枚举桌面快捷方式——这些都在主线程执行，会导致界面卡顿。
- **`pixel_pet.py` 的 ZZZ/爱心浮动**：每 100ms 调用 `setStyleSheet`，这会触发 Qt 样式引擎重新解析，应改用 `QPainter` 绘制。
- **`resizeEvent` 性能**：聊天窗口 resize 时遍历所有消息气泡更新最大宽度，消息多时每个像素的 resize 都会卡顿。
- **`event_engine.py` 的事件保存**：每次记录事件都要 O(n) 遍历日志文件计数，且在锁外执行，存在竞态条件导致重复写入。

#### 4. 工程化缺失

- **测试覆盖率低**：约 70% 的代码没有测试。`bridge.py`、`audio.py`、`updater.py`、`voice_input.py`、所有 UI 模块均为零覆盖。
- **无 CI/CD**：没有 GitHub Actions、没有 lint 配置、没有覆盖率工具。
- **`requirements.txt` 不完整**：只列了 5 个包，但语音功能依赖的 `numpy`、`sounddevice`、`onnxruntime` 等都没列。
- **`build.spec` 排除了 `numpy`**：但语音功能需要它，打包后使用语音会崩溃。
- **无版本锁定**：`requirements.txt` 没有 `==` 或 `~=` 约束，构建不可复现。

### 二、近期改进建议（1-2 周可完成）

**修复已知 Bug**

- 修复 `chat_window.py` 中 `text` 未定义变量
- 补充 `settings_panel.py` 的 `QMessageBox` import
- 修复 ZZZ 颜色值不一致
- 修复 `_on_task_skip` 动画属性错误

**安全加固**

- 扩展 `DANGEROUS_PATTERNS` 覆盖面（增加 `powershell -enc`、`Invoke-Expression`、`cmd /c`、`python -c`、base64 解码、`msiexec`、`certutil -decode` 等）
- 将 shell 命令默认设为需确认，仅 `[APP:...]` 免确认
- 完善 shell 元字符清理（覆盖 `^ < > % !` 等）

**工程基础设施**

- 创建 `pyproject.toml`，统一项目元数据和工具配置
- 补充 `requirements.txt`，添加所有运行时依赖并加版本锁定
- 修复 `build.spec` 中的 numpy 排除问题
- 添加 `.github/workflows/test.yml` 基础 CI

### 三、中期发展路线（v0.3 - v0.5）

#### v0.3 — 稳定性与质量

**目标**：让项目可以"放心交给别人用"。

核心方向：

- **引入结构化日志**：全局替换 `print()` 为 `logging`，统一错误处理策略。目前只有 `event_engine.py` 用了 `logging`，其余全用 `print` 或静默吞掉异常。
- **线程安全修复**：`bridge.py` 的取消机制需要重新设计（建议用递增的 request ID 而非 boolean flag）；`event_engine.py` 的 `_save_events` 需要在锁内执行。
- **配置系统升级**：加入 `config_version` 字段和迁移机制，加入类型校验（防止用户手动编辑 `config.json` 导致的类型错误）。
- **打包可用**：修复 PyInstaller 配置，补全依赖，确保语音功能在打包后可用。考虑用 `cx_Freeze` 或 `Nuitka` 作为备选。
- **测试覆盖到 60%+**：优先覆盖 `bridge.py`（取消逻辑）、`updater.py`（版本比较）、`audio.py`（WAV 生成）和 `markdown_renderer.py`。

#### v0.4 — 用户体验升级

**目标**：从"能用"到"好用"。

可以做的方向：

- **插件系统**：将命令引擎扩展为插件架构。目前的 `[APP/SHELL/CLAUDE]` 标签是硬编码的，可以设计为可注册的 handler，让社区贡献新能力（比如 `[SEARCH:关键词]`、`[TRANSLATE:文本]`、`[SCREENSHOT]`）。
- **对话管理增强**：支持对话分支、消息编辑/删除、搜索历史对话。当前的多会话标签页是基础版，缺少对话内操作。
- **多模态输入**：支持截图发送给 AI（`screen_capture.py` 已有基础）、支持图片粘贴、支持语音实时转录显示。
- **通知系统**：与 Windows 原生通知集成（`winrt` 或 `plyer`），让灵动岛的状态变化也能以系统通知形式触达。
- **性能优化**：将文件 I/O 全部移到工作线程，`resizeEvent` 使用 debounce，ZZZ/爱心改用 `QPainter` 绘制。
- **无障碍支持**：当前零无障碍——所有控件缺少 `setAccessibleName()`，屏幕阅读器完全无法使用。

#### v0.5 — 生态与分发

**目标**：让项目可以被广泛分发和使用。

关键工作：

- **代码签名**：Windows 未签名 exe 会触发 SmartScreen 警告，公开发布前必须解决。可以考虑 SignPath（免费开源项目）或 DigiCert。
- **安装包**：从 PyInstaller onedir 升级为 NSIS/Inno Setup 安装程序，提供开始菜单快捷方式、卸载程序、开机自启配置。
- **多语言**：当前所有 UI 文本硬编码中文。可以引入 Qt 的 `tr()` + `.ts` 翻译文件机制，支持英文和其他语言。
- **主题系统**：`theme.py` 已有设计 token 基础，可以扩展为支持多主题切换（亮色/暗色/高对比度），让用户自定义。
- **MCP 协议支持**：接入 Model Context Protocol，让 BuddyDesk 可以作为 MCP client 调用外部工具服务器，极大扩展能力边界。

### 四、长期愿景（v1.0+）

**跨平台**：PySide6 本身支持 macOS 和 Linux，但当前代码大量使用 Windows 特有 API（`ctypes.windll`、`winsound`、注册表操作、`.lnk` 解析）。抽象出平台层后，可以用较低成本扩展到全平台。

**Agent 模式**：当前 AI 只能被动回答或执行单步命令。可以引入多步任务规划（类似 AutoGPT 的思路），让宠物能够自主完成复杂任务链，比如"帮我整理桌面上的截图到 Documents/Screenshots 并按日期重命名"。

**社区生态**：插件市场、宠物皮肤工坊（社区制作像素宠物精灵图）、共享命令配方（类似 Alexa Skills）。

**本地 AI 优先**：随着本地模型（Llama、Qwen 等）越来越强，可以深度整合本地推理，减少 API 依赖，让核心功能完全离线可用。

### 五、各维度评分一览

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构设计 | 8/10 | 分层清晰，信号/槽解耦好，Strategy 模式用得当 |
| UI/UX 设计 | 7/10 | 视觉质量高，灵动岛和像素猫都很有特色，但有动画生命周期和性能问题 |
| 安全性 | 4/10 | 危险命令检测是好的起点，但黑名单模式本质脆弱 |
| 测试覆盖 | 3/10 | 已有测试质量不错，但覆盖面严重不足 |
| 工程化 | 3/10 | 缺 CI、缺 lint、缺打包配置、依赖不完整 |
| 文档 | 6/10 | 模块级 docstring 很好，但无 API 文档、无架构图、无贡献指南 |
| 可分发度 | 4/10 | PyInstaller spec 存在但有 bug，缺签名、缺安装程序 |

**总结**：BuddyDesk 的核心创意和架构设计是扎实的，"桌面宠物 + 灵动岛 + AI 命令执行"的组合很有吸引力。当前最大的短板在工程化和安全加固——这两个方向投入 2-3 周就能让项目达到可以公开发布的质量水平。
