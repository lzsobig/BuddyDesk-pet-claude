# BuddyDesk 长期路线图（v0.4 → v1.0+）

> 制定时间：2026-06-16
> 与 `docs/IMPROVEMENT_PLAN.md`（短期 P0-P2 修复）配套。
> 本文档覆盖**功能演进、架构演进、生态、跨平台**四个维度，每个版本一个里程碑。

---

## 0. 路线图总览

```
v0.4  感知闭环        —— 让宠物真正"看见/听见"桌面，补齐半成品
v0.5  Agent 能力      —— 从单步命令到多步自主任务
v0.6  分发工程化      —— 安装包、签名、自动更新、崩溃回收
v0.7  生态扩展        —— 插件系统、皮肤工坊、命令配方
v1.0  跨平台 + 离线   —— macOS/Linux、本地模型优先
```

**核心判断**：BuddyDesk 的差异化护城河是「**会感知桌面的 AI 宠物**」，不是「又一个 AI 聊天框」。所以 v0.4 的第一优先级是把感知能力补闭环——目前截图、嗅图标都是半成品（详见下文），地基没夯实就往上盖功能是空中楼阁。

---

## 1. 现状基线（已逐行核实，决定后续方向）

在规划未来前，必须先认清"手头有什么"。以下均经源码核实：

| 能力 | 成熟度 | 证据 |
|------|--------|------|
| 灵动岛 + 桌宠 + 聊天三件套 | ✅ 完整 | 5 状态交叉淡入、7 状态桌宠防闪烁 |
| 命令标签执行（APP/SHELL/CLAUDE） | 🟡 有安全债 | 黑名单 + shell=True，IMPROVEMENT_PLAN P0-1 处理 |
| AI 后端（Claude CLI / OpenAI / Anthropic 直连） | ✅ 完整 | 流式 + 取消（取消机制有 bug，P1-1） |
| 语音输入（SenseVoice 本地 ASR） | 🟡 半闭环 | 录音→RMS 电平→后台推理→回调**已通**，但只到"填入输入框"，无 TTS 回复、无实时流式 |
| 截图快门 | ❌ **半成品** | `screen_capture.capture_screen_async` 写好了，但 `main.py` **没注册 ⌘⇧J 快捷键**，截图结果也没接进 chat |
| 嗅桌面图标 | ❌ **半成品** | `desktop_icon_reader.get_icon_at_position` 直接 `return None`，作者注明"简化方案" |
| Pin 桌面卡片 / 拖文件给桌宠 / 任务派发卡片 | ✅ 已实现 | ui/pin_card.py、drag_drop_util.py、SYSTEM_PROMPT 有 tasks 块 |
| 打包（PyInstaller） | 🟡 有 bug | build.spec 排除 numpy（P1-2），无签名无安装程序 |
| 测试 / CI | 🟡 弱 | 集成测试混在单测里，仅 build.yml 无 test.yml |

**结论**：v0.4 的首要任务不是堆新功能，而是把「截图」「嗅图标」这两个**已开工但没收尾**的能力做闭环，并让语音双向化。这是 ROI 最高的一步。

## 2. v0.4 —— 感知闭环（预计 2-3 周）

**目标**：让宠物从"被动等你打字"变成"主动感知桌面"。这是产品差异化的核心。

### 2.1 截图快门闭环（接上断线）⭐ 最高

现状：`screen_capture.py` 写好了，`main.py` 没接。

- 在 `main.py._setup_hotkeys` 注册 `Ctrl+Shift+J`：调 `capture_screen_async`，结果回调里把 png_bytes 加进 `chat_window.pendingImages`，自动附带一句"我看了下屏幕，…"
- 截图自动排除 BuddyDesk 自己的窗口（桌宠/聊天/岛/设置）——`screen_capture` 注释里写了要做，实际没实现。用各控件的 `winId()` 比对。
- 灵动岛状态联动：截图时 island 显示"📸 看一眼"。

**DoD**：按 `Ctrl+Shift+J` → 闪光 → 截图进对话 → AI 能"看图回答"（需后端支持多模态，见 2.4）。

### 2.2 嗅桌面图标做实（从 return None 到真能嗅）

现状：`get_icon_at_position` 是空壳。要做"宠物真的能感知桌面"必须补上。

- **Windows 桌面图标位置**：用 `IShellFolder` COM（pywin32）枚举桌面图标坐标。这是 HermesPet macOS 版 `osascript` 的 Windows 等价物，目前完全缺失。
- 拖桌宠到桌面 → `get_icon_at_position(x, y)` 返回最近图标 → 桌宠停下嗅 → 图标名发 AI → 短评。
- **退路**：若 COM 太重，先做"桌宠随机走到一个 .lnk 附近嗅"（不需要精确坐标），作为 v0.4 兜底，精确坐标放 v0.5。

**DoD**：拖桌宠到桌面某图标 → 嗅 → 灵动岛显示 AI 短评。

### 2.3 语音双向化（从单向输入到对话）

现状：ASR 单向通（用户说→文字），AI 回复是文字。

- 加 TTS：让桌宠"开口说话"。选项：
  - **本地优先**：edge-tts（免费、音质好、需联网）或 pyttsx3（完全离线、机械音）
  - 建议 edge-tts 起步，配置项可切离线引擎
- 触发点：AI 流式回复完成时，可选朗读（`user_config["tts_enabled"]`）
- 桌宠口型同步：happy 帧循环 + 说话时长匹配 TTS 时长
- **实时转录**（可选）：录音过程中边录边显字（SenseVoice 流式），而非录完整段才识别。体验提升大但改动大，列为 v0.4 选做。

**DoD**：说一句话 → 桌宠识别 → AI 回答 → 桌宠朗读回答（开关可控）。

### 2.4 多模态后端对接

2.1 的截图要"AI 看图回答"，需要后端支持图片输入。

- `OpenAIBackend.send_message` 支持图片：messages 里 content 用 `[{type:text},{type:image_url}]` 结构。OpenAI / DeepSeek-vl / 通义千问 VL 都兼容。
- `ClaudeCodeBackend`（CLI）多模态能力受限，标注"截图功能建议用 OpenAI 后端"。
- 配置项 `vision_enabled`：关闭时截图只存图不发 AI。

**DoD**：OpenAI 后端下，发截图 → AI 描述/回答画面内容。

## 3. v0.5 —— Agent 能力（预计 3-4 周）

**目标**：从"执行单步命令"进化到"自主完成多步任务"。这是从工具到 Agent 的跃迁。

### 3.1 多步任务规划与执行

现状：任务派发卡片（tasks YAML）能渲染，但每个任务是**独立单步**，不能链式。

- 引入任务执行器：解析 tasks 块后，按依赖/顺序执行，每步结果喂给下一步。
- 状态机：`planning → executing → reviewing → done/failed`，每步灵动岛实时反馈。
- 失败回滚/重试：单步失败时桌宠变 sad，问用户"重试/跳过/中止"。
- 例："整理桌面截图到 Documents/Screenshots 并按日期重命名" → AI 规划成 [枚举桌面图片 → 创建目录 → 移动 → 重命名] 多步，逐步执行。

**风险**：多步 + shell 执行 = 安全风险放大。**强依赖** IMPROVEMENT_PLAN P0-1 的确认机制，且每步都要确认（除非用户对整个任务链授权）。

### 3.2 桌面上下文记忆

- 短期：当前会话内，宠物记住"你刚打开过微信""你5分钟前查过 IP"
- 长期：跨会话的轻量记忆（用户可选开关，隐私可控）。存在 `~/.buddydesk/memory.json`，只存用户显式确认的事实（"我叫小王""我是做设计的"）。
- **不做**：被动采集/早报周报/共享记忆（PLAN.md 已明确否决，隐私负担重）。

### 3.3 主动触发（情景感知）

现状：宠物纯被动。

- 检测到剪贴板内容（已实现）→ 主动问"要帮你处理这个吗？"
- 检测到长时间无操作 → 桌宠打瞌睡（已有 sleep 状态，可加"你好像离开了一会儿"）
- 检测到特定应用前台（可选，需 Windows API）→ 上下文提示（如在 VSCode 前台时，宠物说"要帮你写代码吗？"）
- **原则**：主动但不打扰，所有主动行为可关。

## 4. v0.6 —— 分发工程化（预计 2-3 周）

**目标**：让普通用户能"下载、安装、自动更新"，像正经软件一样。这是从"能跑"到"能卖/能广为分发"的鸿沟。

### 4.1 安装程序

现状：PyInstaller onedir，用户拿到一堆文件。

- 用 **Inno Setup** 或 **NSIS** 打成单 exe 安装包
- 含：开始菜单快捷方式、卸载程序、开机自启选项、文件关联（可选）
- 安装时可选安装路径、创建桌面快捷方式

### 4.2 代码签名

现状：未签名，SmartScreen 会拦截。

- **SignPath**（开源项目免费）或 DigiCert 付费证书
- 没签名 = 普通用户看到"Windows 已保护你的电脑"直接放弃。这是分发的硬门槛。

### 4.3 自动更新做实

现状：`updater.py` 写好了，但 `main.py:166` 被注释禁用（"本机 SSL 连 GitHub 段错误"）。`_GITHUB_REPO` 还是占位符 `your-org/BuddyDesk`。

- 修复 SSL 问题（换用 `requests` + certifi，或配置系统证书）
- `updater._GITHUB_REPO` 改成真实仓库
- 启用 `main.py` 的更新检查（当前注释掉的那行）
- 加"下载并安装"（当前只通知，需用户手动下载）——可选，先做通知，下载安装放 v0.7

### 4.4 崩溃回收闭环

现状：`crash_reporter.py` 能扫本地崩溃日志、复制到剪贴板、开 GitHub Issue。

- 接入 Sentry / 自建上报端点（用户 opt-in）
- 或保持"复制到剪贴板手动上报"（隐私友好，但收集率低）
- 至少：崩溃时弹窗引导用户上报，而非静默退出。

## 5. v0.7 —— 生态扩展（预计 4 周+）

**目标**：让社区能贡献能力，从"单人作品"变"平台"。

### 5.1 命令 handler 插件化 ⭐（架构基础）

现状：`[APP/SHELL/CLAUDE]` 硬编码在 `parse_and_execute` 的 `re.findall` 里。

- 改成可注册的 handler 注册表（IMPROVEMENT_PLAN P3-1 已提及，这里落地）：
  ```python
  @register_command("SEARCH", needs_confirm=False)
  class SearchHandler:
      def execute(self, args) -> CommandResult: ...
  ```
- 每个 handler 声明是否需确认、危险等级、帮助文本
- 内置 handler（APP/SHELL/CLAUDE/SEARCH/TRANSLATE/SCREENSHOT）+ 用户自定义
- 插件目录 `~/.buddydesk/plugins/`，启动时扫描加载

### 5.2 皮肤工坊

现状：橘猫 72 帧硬编码。

- 皮肤格式规范：一个文件夹含 `manifest.json`（状态→帧映射）+ 帧图片
- 内置橘猫，社区可做：柴犬、兔子、像素人、二次元角色
- 设置面板里切换皮肤，桌宠 `set_state` 自动适配新帧表
- **注意**：帧命名/状态映射要向后兼容，别破坏现有橘猫

### 5.3 共享命令配方

- 类似 Alexa Skills：用户把"说 X → 做 Y"的配方导出/导入
- 格式：`{trigger: "打开工作模式", actions: [APP:vscode, APP:chrome, SHELL:...]}`
- 社区分享配方，一键导入

## 6. v1.0 —— 跨平台 + 离线（预计 6 周+）

**目标**：让 BuddyDesk 不只是 Windows 软件。

### 6.1 跨平台（macOS / Linux）

现状：大量 Windows 特有 API（`ctypes.windll`、`winsound`、注册表、`.lnk` 解析、`IShellFolder`）。

- 抽象平台层：`platform/windows.py` / `platform/macos.py` / `platform/linux.py`
- 每个平台实现统一接口：`find_app()` / `hotkey` / `audio_play()` / `lnk_resolve()`
- PySide6 本身跨平台，UI 层基本不用改
- **难点**：v0.4 的 COM 嗅图标（2.2）是 Windows 专属，macOS 要用 `osascript`/NSWorkspace 另写

### 6.2 本地 AI 优先

现状：依赖 Claude CLI / OpenAI API，完全联网。

- 深度整合 **Ollama**（OpenAIBackend 已兼容 `localhost:11434`，但体验粗糙）
- 本地模型推荐：Qwen2.5 / Llama3.2 / GLM4（中文场景 Qwen 优先）
- 语音也离线：SenseVoice 已是本地 ASR；TTS 用 pyttsx3 或本地 Coqui TTS
- 目标：核心功能（聊天 + 命令 + 语音输入）完全断网可用，只在用户选联网模型时才联网

### 6.3 i18n（多语言）

现状：UI 全中文硬编码。

- Qt `tr()` + `.ts` 翻译文件机制
- 先做英文，再社区贡献其他语言
- **注意**：SYSTEM_PROMPT 也需分语言版本（命令标签语法不变，但自然语言描述变）

## 8. 不做的事（明确否决，避免反复讨论）

| 想法 | 否决理由 |
|------|----------|
| 早报/周报/自动采集用户行为 | 隐私负担重，与"桌面伴侣"定位冲突 |
| 5 个 AI 引擎真并行 | 工程成本数量级，3 后端已够用 |
| 知识云图（HermesPet v1.3） | 视觉炫但实施成本极高，不解决核心痛点 |
| 商业化/付费墙 | 个人项目定位，社区驱动 |
| 后端云服务/账号系统 | 增加运维负担和隐私风险，保持本地优先 |

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| Agent 多步执行失控（删库等） | 强制每步确认 + 操作前快照 + 限制工作目录 |
| COM/平台 API 深度依赖导致跨平台困难 | v0.4 起就预留平台抽象层，别把 Windows 代码写死到 UI 层 |
| 本地模型能力不足导致体验差 | 本地作为"离线兜底"，联网模型作为"增强"，而非二选一 |
| 插件系统引入安全风险（恶意插件） | 插件沙箱化 + 签名 + 用户显式启用，默认不自动加载第三方 |
| 自动更新被中间人篡改 | 签名 + 校验包哈希 + HTTPS |

## 10. 执行说明（给 Claude Code）

本路线图是**长期规划**，不是即时指令。使用方式：

1. **每个版本里程碑单独规划**：要做 v0.4 时，先开一份 `docs/PLAN_v0.4.md`，把本图的 2.1-2.4 展开成具体任务（参考 PLAN.md 的粒度）。
2. **先做完 IMPROVEMENT_PLAN 的 P0/P1 再碰 v0.4**：地基没夯实别盖楼。截图闭环依赖命令安全（P0-1），语音双向依赖不崩（P0-3/4）。
3. **"半成品"优先**：v0.4 的 2.1（截图接上）、2.2（嗅图标做实）是把已有代码补完，ROI 远高于全新功能。
4. **每个能力都先做最小闭环**：截图先做"截→发→AI 答"，别一上来就做区域选择/标注。嗅图标先做"随机嗅一个"，别一上来就做精确坐标。
